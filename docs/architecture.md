# Архитектура

## Проект

Lyceum публикует русские выжимки технических статей в канал Telegram. Под постом читатели оставляют комментарии: у канала включено обсуждение, к нему привязана группа комментариев. Это не форум и не супергруппа с ветками. Отдельных веток Web и AI нет.

Оператор присылает боту ссылку, чужой текст или готовый пост, проверяет выжимку и только после этого выпускает её в канал.

У поста есть тема: Django, FastAPI, Postgres, модели, агенты. Тема — подпись материала, а не место в Telegram. Все темы выходят в один канал.

Один процесс на VPS, одна база, один канал. Второе направление не требует нового репозитория.

В `.env` уже лежат `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`. Значения в репозиторий не попадают.

## ТЗ

Один оператор. Читатели в канал ничего не присылают, они пишут комментарии под постами.

Этот срез делает:

- принимает источник `url`, `raw_text` или `ready_post`;
- для ссылки скачивает страницу и забирает основной текст;
- строит русскую выжимку, кроме готового поста: его текст идёт на модерацию как есть;
- показывает карточку модерации;
- публикует в канал только после одобрения и только если выбрана тема;
- пишет публикацию: чат канала, `message_id`, ссылка на пост.

Этот срез не делает: серии и расписание, рекламу, почту Medium, Telegraph, деплой.

Правила:

- текст короче 400 символов не доходит до модерации, карточка просит вставить текст; для готового поста пустой считается только пустая строка;
- выжимка, которая уходит в канал, не длиннее 4096 символов;
- «Опубликовать» без темы недоступно;
- в конце кнопок карточки стоит «Новая тема»: бот запоминает статью и просит название; следующее сообщение создаёт тему и сразу выбирает её, карточка приходит ещё раз;
- `/theme Redis` без открытой статьи добавляет тему и подтверждает это, к посту тема не крепится, пока её не выберут на карточке;
- повторный approve не шлёт второе сообщение;
- отклонение ничего не публикует;
- кнопка «в серию» отвечает, что серия будет в следующем срезе, и не публикует.

Комментарии включает привязка обсуждения в настройках канала. Бот не пишет в группу комментариев и не передаёт `message_thread_id`.

## Слои

Зависимости смотрят внутрь: handlers → application → domain. infrastructure реализует протоколы domain и не вызывает сценарии.

- **domain** — тема, статья, публикация, статусы, протоколы репозиториев, `Summarizer`, `ArticleFetcher`, `Publisher`. Без aiogram, SQLAlchemy, httpx.
- **application** — сценарии модерации. Не знают, какая база и какая модель.
- **infrastructure** — SQLite через SQLAlchemy 2, скачивание страницы (httpx + trafilatura), саммари через `cursor-sdk`, заготовка отправки в канал.
- **handlers** — клавиатура карточки, команды лички и callback-кнопки. Без бизнес-правил.

Сценарии синхронные. Репозиторий подставляется снаружи, поэтому смена на Postgres — новый класс репозитория и другая строка подключения. Сценарии не меняются.

## Статусы статьи

`received` → `extracted` → `awaiting_review` → `rejected` или `published`.

`published` ставится после успешного ответа Telegram. Имена `approved` и `scheduled` в перечислении есть для серии, переходов в них в этом срезе нет.

- `submit_url` сохраняет статью, скачивает текст, делает выжимку, ставит `awaiting_review`.
- `submit_text` делает то же без скачивания.
- `submit_ready_post` кладёт текст на модерацию как есть и не вызывает `Summarizer`.
- Короткий текст не доходит до `awaiting_review`.
- `choose_theme` записывает тему. Карточка показывает выбранную тему.
- «Новая тема» на карточке запоминает статью так же, как «Править», и ждёт название следующим сообщением. Название после обрезки пробелов становится и подписью кнопки, и slug. Пустое название и название длиннее 80 символов не записываются: оператор получает текст, что название не подошло. Тот же текст второй раз новую строку не создаёт: бот пишет, что тема уже есть, и выбирает её для этой статьи. Карточка приходит снова, «Опубликовать» доступно. `/url`, `/text` и `/post` это ожидание сбрасывают.
- `/theme` с названием добавляет тему без статьи. В ответ — подтверждение. К посту она не прикрепляется, пока её не выберут на карточке. Команда не затирает уже существующие темы.
- `edit_summary` меняет выжимку и снова отдаёт карточку.
- `regenerate` ещё раз вызывает `Summarizer`. Для готового поста саммари не строится. Если за время выжимки статью отклонили, сохранение не возвращает её на карточку модерации.
- `reject` ставит `rejected` и не вызывает `Publisher`.
- `approve` без темы `Publisher` не вызывает. С темой публикует один раз в канал и ставит `published`.

`Publisher` в тестах запоминает сообщение. Рекламной пометки в тексте поста нет.

## Темы и публикация

Тема — строка `themes`: заголовок, slug. У статьи хранится `theme_id`. Тема не выбирает чат и не выбирает тред. Куда публиковать, решает `TELEGRAM_CHAT_ID`, не название темы.

Начальный набор, если тем ещё нет: Django, FastAPI, Postgres, модели, агенты. Повторный запуск и `/theme` его не затирают и не дублируют. Новая тема из лички добавляется к этому набору.

Публикация — строка, которая появляется в момент отправки и дальше не меняется: `article_id`, `telegram_chat_id`, `telegram_message_id`, `url`, `published_at`. Ссылка на предыдущую часть серии потом берётся отсюда. `telegram_chat_id` — `BigInteger`: id канала не влезает в обычный `Integer`.

Чат канала — `TELEGRAM_CHAT_ID` в окружении. Для публичного канала это `@username`, для частного — id вида `-100…`.

## База

Ревизия `0001_initial` создаёт `themes`, `articles`, `publications`. Таблицы `topics` нет. Движок сейчас SQLite. Тесты вызывают `alembic upgrade` только для временного файла: URL передаётся в `config.attributes["database_url"]` и перекрывает и `DATABASE_URL`, и `alembic.ini`.

Схема меняется новой ревизией Alembic, либо правкой `0001_initial`, если она ещё не применена. `alembic upgrade head` на рабочей базе и на VPS делаю я сам.

Серия в эту ревизию не входит. В следующем срезе у публикации появятся серия, номер части и ссылка на предыдущую публикацию.

## cursor-sdk

`SUMMARIZER=cursor` включает адаптер `Summarizer`. Ключ — `CURSOR_API_KEY` из Cursor Dashboard → API Keys. Адаптер вызывает официальный `cursor-sdk`: облачный агент без репозитория, текст ответа агента. Это не клиент `/v1/chat/completions` и не прокси к внутренним адресам Cursor. Сценарии флаг не читают. При `SUMMARIZER=fake` адаптер отказывается строить выжимку и Cursor не вызывает.

Саммари в тестах — заглушка с фиксированным текстом. Живой Cursor API из тестов не вызывается.

## Следующие срезы

- серия принадлежит теме; в канале один пост в день; простой не догоняется пачкой; в тексте ссылка на предыдущую часть из `publications`
- реклама сообщением в тот же канал, пометка «Реклама» в шаблоне, отдельной ветки нет, слот не совпадает со слотом серии
- приём почты Medium как ещё один способ получить ссылку

В этот список не входят и в этом срезе не делаются: Telegraph, systemd, деплой.
