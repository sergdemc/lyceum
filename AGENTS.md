# Lyceum — инструкции для Cursor Agent

Бот принимает ссылку, чужой текст или готовый пост, делает русскую выжимку и показывает карточку модерации. В канал ничего не уходит, пока пост не одобрен и не выбрана тема. Читатели комментируют посты в обсуждении канала. Форум с ветками не используется.

Подробности среза — в `docs/architecture.md` и `README.md`.

## 1. Сначала существующая реализация

Перед новым кодом найди:

- сценарий в `src/lyceum/application/moderation.py` и карточку в `application/cards.py`;
- протоколы в `src/lyceum/domain/protocols.py`;
- адаптер в `infrastructure/`;
- обработчик в `handlers/`;
- тест рядом с поведением: `tests/test_moderation.py`, `test_layers.py`, `test_adapters.py`, `test_keyboards.py`, `test_migration.py`.

Не заводи второй сервис, протокол или адаптер, если текущий можно расширить.

## 2. Слои

Зависимости смотрят внутрь: handlers → application → domain. infrastructure реализует протоколы domain и не вызывает сценарии.

- domain не импортирует aiogram, SQLAlchemy, httpx, trafilatura, Alembic, APScheduler, cursor_sdk, application, infrastructure, handlers, config.
- application не знает базу, Telegram и config.
- handlers без бизнес-правил и без infrastructure.
- Сценарии синхронные. Репозиторий подставляется снаружи.

Граница зафиксирована в `tests/test_layers.py`. Новый запрет добавляй туда же.

Смена SQLite на Postgres — новый класс репозитория и другая строка подключения. Сценарии не меняются. В этом срезе замены нет.

## 3. Поведение модерации

- `submit_url` и `submit_text` принимают текст, строят выжимку и ставят `awaiting_review`. Ссылка ещё и скачивается.
- `submit_ready_post` кладёт текст как есть и не вызывает `Summarizer`.
- Текст короче 400 символов не доходит до модерации. Для готового поста пустой считается только пустая строка.
- Выжимка, которая уходит в канал, не длиннее 4096 символов.
- `approve` без темы не вызывает `Publisher`. С темой публикует один раз и ставит `published`.
- «Новая тема» в конце кнопок карточки запоминает статью и ждёт название. Следующее сообщение создаёт тему (заголовок и slug — текст без краевых пробелов) и сразу выбирает её. Пустое название и название длиннее 80 символов не пишутся в базу: оператору текст, что название не подошло. Тот же текст второй раз не дублирует строку, а выбирает существующую. `/url`, `/text` и `/post` это ожидание сбрасывают.
- Если статью отклонили, пока считается выжимка, сохранение не возвращает статус `rejected` на карточку модерации.
- `/theme Название` без открытой статьи добавляет тему и подтверждает. К посту она не крепится, пока её не выберут на карточке. Канал публикации задаёт `TELEGRAM_CHAT_ID`, не название темы. Начальные пять тем команда не затирает.
- Повторный approve не шлёт второе сообщение. `reject` ничего не публикует.
- Кнопка «в серию» не публикует.

## 4. Секреты и внешние вызовы

Секреты только в `.env`. Образец имён — `.env.example`. Не подставляй токен бота, `CURSOR_API_KEY` и id чата в код, тесты и ответы.

Не вызывай живой Telegram и Cursor API. Тесты без сети: скачивание, саммари и отправка — заглушки. `CURSOR_API_KEY` для тестов не нужен.

## 5. Проверка

Перед завершением нетривиального изменения:

```bash
make test
```

Это `uv run pytest`. Не пиши, что тесты прошли, если команда не запускалась.

`make migrate` и `alembic upgrade` на базу не запускай. Дай команду пользователю. Тесты сами накатывают ревизию на временный файл SQLite.

## 6. Вне этого среза

Не добавляй серии и расписание, рекламу, почту Medium, Telegraph и деплой. Бот запускается `make run`: long polling, команды `/url`, `/text`, `/post`, `/theme`. `SUMMARIZER=cursor` включает облачного агента без репозитория. Сценарии флаг не читают: адаптер выбирается снаружи. В тестах саммари — заглушка, живой Cursor API не вызывается.
