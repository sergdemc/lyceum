# Lyceum

Бот принимает ссылку, чужой текст или готовый пост, делает русскую выжимку и показывает карточку модерации. В канал ничего не уходит, пока пост не одобрен и не выбрана тема.

Читатели сидят в канале и оставляют комментарии под постами. Для этого у канала включено обсуждение. Django и FastAPI — темы поста, не ветки Telegram. Форум с ветками Web и AI не используется.

Серии, реклама и деплой сюда не входят. Саммари через cursor-sdk включается флагом `SUMMARIZER=cursor`; тесты остаются на заглушке.

## Запустить бота

Сначала сами накатите миграцию на свою базу: `make migrate`. Потом:

```bash
make run
```

Команда вызывает `uv run python -m lyceum`. Бот читает `.env` и слушает личку. В `TELEGRAM_CHAT_ID` на время проверки нужен id тестового канала. При `SUMMARIZER=fake` выжимка не строится.

## Поставить зависимости

Нужны Python 3.12 и [uv](https://docs.astral.sh/uv/).

```bash
make sync
```

`make sync` создаёт `.venv`, ставит зависимости и записывает `uv.lock`. `make install` делает то же самое.

Секреты лежат только у вас. Образец имён переменных — в `.env.example`.

## Прогнать тесты

```bash
make test
```

Команда вызывает `uv run pytest`.

Тесты поднимают временный файл SQLite и накатывают на него Alembic. Сети нет: скачивание, саммари и отправка подменены заглушками. `CURSOR_API_KEY` для тестов не нужен.

`pytest` не читает вашу базу. Даже если в окружении задан `DATABASE_URL`, ревизия в тестах идёт в файл внутри каталога pytest.

## Применить миграцию самому

Push на GitHub и миграцию на VPS делаю я. Ревизия в репозитории уже есть, на рабочую базу её не накатывали.

Локально, когда база нужна вам:

```bash
# либо поправьте sqlalchemy.url в alembic.ini,
# либо экспортируйте DATABASE_URL, например:
# export DATABASE_URL=sqlite:///./data/lyceum.db
make migrate
```

Без `DATABASE_URL` Alembic берёт `sqlalchemy.url` из `alembic.ini` (`sqlite:///./data/lyceum.db`).

Замены SQLite на Postgres в сценариях нет: другой репозиторий и другая строка подключения. См. `docs/architecture.md`.
